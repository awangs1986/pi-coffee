# PI Coffee Web — 真机验收清单（浏览器 / 网络 / 文件系统）

本文档列出**只能在真实环境验证**的前端行为，供人工逐条测试。自动化已覆盖的部分（结构契约 `test/web-shell.test.ts`、DOM 行为 `test/render-dom.test.ts`、全部后端用例，共 ~170 项）不在此重复。

## 0. 环境与准备

1. 启动服务（示例）：
   ```bash
   PI_COFFEE_WEB_BIND=0.0.0.0 PI_COFFEE_HOST_BIND=0.0.0.0 \
   PI_COFFEE_HOST_TOKEN=<token> PI_COFFEE_ALLOW_UNAUTHENTICATED=1 \
   npm start
   ```
   期望：Web `http://<host>:3000/`，Host WS `ws://<host>:8788/host`。
2. 打开首页，期望：侧栏（对话列表）、中栏（Hero 或对话）、右栏（变更面板，宽屏默认展开）、底部 Gitea 上下文章（仅在有项目后显示）。
3. 若通过反向代理/平台预览打开 Web 失败：确认 Web 与 Host 都绑定 `0.0.0.0`；确认代理透传 WebSocket 升级（`/ws` 路径）；打开浏览器 DevTools 确认 `/ws` 握手 101，页面控制台无 `Refused to connect` / 混合内容错误。

## 1. 连接与重连

| # | 步骤 | 期望 |
|---|------|------|
| 1.1 | 打开页面后断开网络（或 `kill` Host 进程） | 1.2 秒内：左下状态变「连接断开，重连中…」红点；**中栏顶部出现浅黄色横幅**「连接已断开，正在自动重连…（Host 上的任务不会被打断）」；输入卡可打字但发送钮禁用 |
| 1.2 | 恢复网络 / 重启 Host | 横幅消失，状态变「已连接」绿点；当前对话历史自动重放；过程中输入的草稿仍在 |
| 1.3 | 断线期间点发送 | 无消息落库、无报错弹窗；恢复后可正常发送 |
| 1.4 | 运行中任务时断线重连 | 横幅出现→消失；Host 任务不中断；重连后新事件继续流入；若有未补放输出显示一次「部分未能补放」提示 |

## 9. 真实平台/代理注意事项

- 平台预览打不开时先查第 0 节第 3 条；WebSocket 失败会表现为持续 1.1 横幅。
- HTTPS 入口下文件上传走 Transfer Server，其 advertise 地址必须浏览器可达；HTTP 混合内容会被浏览器拦截。
- 浏览器只能访问 Web 入口，不允许直连 VM 内部服务；跨用户/跨对话的文件访问应返回 401/403（配合后端用例验证一致性）。
