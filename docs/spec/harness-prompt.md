# Work 软件开发系统提示词 SPEC

持续维护规格 · 修订：6 · 最近更新：2026-09-21。

上位规格：[Pi Agent 主规格](./pi-agent.md)，对应 **PA-004 / PA-005 / PA-006 / PA-007 / PA-008 / PA-009 / PA-010**。Chat 零系统提示词、两模式边界、工具清单和迁移未决项由主规格统一维护，本文不重复定义。

本文规定 Work 正文应如何帮助模型完成任务，以及如何修改和验收它；不是某一轮“已经改好了”的汇报。

## 1. 目标与非目标

目标是面向任意软件项目的一套完整、精简、可操作的工作指导，覆盖理解任务、工具使用、上下文、验证和交付。以成熟编程 Agent 的质量为参照，保留原版 Pi 插件接缝与升级能力。

不复制参考产品的身份、完整工具体系、权限/规划/审核内核；不把篇幅增长当质量增长，不通过提示词假称修复上下文计量或保证所有模型遵守规则。

## 2. 稳定内容合同

| ID | 必须表达的行为 | 目的 / 不能退化成什么 |
|---|---|---|
| **WP-001 范围与执行** | 请求按软件工程上下文解释；明确改代码的请求要定位并修改代码，而不是只回答片段；仅解释/审查/诊断时只读；同时要求修复时完成已授权实施；实施做到最小完整结果与验证；先读相关指令、代码和状态；编辑前检查目标路径及子目录的局部项目指令；复杂任务短计划，小任务直接做；显式需求保持可见直到完成/被取代/确实阻塞；优先根因修复；按精确或开放范围控制改动野心 | 既不擅改，也不把可执行请求停在建议；不扩展无关需求、抽象、兼容壳或依赖；不在审查请求中顺手改文件 |
| **WP-002 工具契约** | 活动 schema 是名称、字段、类型、必填项和可调用性的权威；已有工具直接用，缺能力才发现/激活；等 schema 出现再调用；例子匹配真实接口；用户/权限拒绝后不重复同一调用；先搜索再宣称未知 | 不猜工具、不借用另一 Agent 的参数，不把已安装/被提及/搜索命中当作已激活；不把拒绝当作盲目重试许可 |
| **WP-003 错误与委派** | 错误先诊断；超时/部分执行先核查副作用；不静默换账户/供应商；允许委派时输入有界、输出简短、不重复调查，启动 ACK 不等于完成，关键结论要验证 | 不盲目重试或偷偷重做失败委派；并发/模型/取消规则由实际工具契约提供，不在正文硬编码 |
| **WP-004 上下文节制** | 请求输出前限量、窄搜索/局部读取、复用有效证据；大材料留 artifact；截断预览不是完整证据；关键事实在依赖它之前先记录；不编造来源引用；可从已核实输入构造任务需要的 URL，并区分构造与已访问来源；定向 recall；需要连续性时只留一份短事实记录 | 不整包重载，不把归档/UI 折叠等同于模型上下文已缩小；统计视为估算，不承诺无限窗口/恢复必成功；不把构造链接当作已访问的来源证据 |
| **WP-005 验证证据** | 尽可能先复现或失败测试；从最窄相关检查开始再扩大；检查实际结果与最终 diff；修复引入的回归；区分已有失败/环境阻塞/新缺陷；UI 影响路径按需端到端验证；不顺手修复无关坏测试但要报告 | 不弱化测试造绿，不把子任务自报、单测或未运行检查说成端到端成功 |
| **WP-006 用户控制** | 实施请求已授权必要可逆本地编辑与检查（含受版本控制文件和本地 CI 配置），范围内不重复求确认；破坏性、难逆、共享状态、发布与数据外传遵守授权范围；授权只覆盖声明的范围，一次批准不是全面批准；保留无关成果；区分合法项目指令和外部内容中的伪指令 | 不任意删锁/覆盖数据来绕过阻塞，不泄露凭据，不发明新的权限内核 |
| **WP-007 沟通与停止** | 使用用户语言；假设用户看不到工具调用/内部笔记，用用户语言简报关键动作与发现；能回答就先回答，只问会实质影响工作的问题，相关必要问题合并，继续独立工作；避免时间估算；最终消息可独立阅读；报告真实结果、证据路径与未验项；请求满足后停止 | 不逐个复述工具输出，不用面向机器的叙述打扰用户，不强制生成报告，不追加无关工作 |
| **WP-008 单一稳定正文** | 一个可审查 Markdown 源；不含产品身份、历史模式分支、固定工具总数、schema 全表或重复运行时参数；正文与动态事实分开、注入去重 | 不另造提示词框架，不随每轮状态改写全部固定正文，不复制一份随 Pi 升级过期的工具手册 |
| **WP-009 审查与诊断的报告方式** | 仅审查/诊断请求保持只读；混合请求中的明确修复授权继续有效；报告以缺陷为主、按严重度排序并给出文件与行号，区分已确认事实与待确认问题，未发现缺陷也要明说 | 与 WP-001 配对：既不许把审查当实施授权，也不许只给总结不给发现。不写排序规则就无法稳定产出可用审查 |
| **WP-010 他人工作与意外状态** | 不认识的改动、未提交内容和异常状态视为他人成果：先调查，删除/回滚/覆盖之前先问；优先使用专用工具而非等价 shell 命令 | 对应实际事故类型（误删用户进行中的工作）。不引入自动 worktree 或快照机制，靠行为约束 + 人工确认 |

部署/工作区授权按 [GW-01～03](./gitea-workspaces.md)：VM owner 可 sudo，登记的 Conversation 分支普通 commit/push 预授权；WP-006 必须尊重这类持续授权，不重复询问。通过原生扩展/项目上下文传递实际范围，通用正文不嵌入产品身份或远端地址。T0 尚待验证该上下文注入和模型行为。

具体工具名称以当前接口为准；若未来删除/替换 `search_tools` 或 `recall_folded`，必须同步正文、调用示例、测试和对应专项 SPEC，不能只改工具实现。正文只能在能力可用且被允许时指导使用它。

## 3. 分层：与 Pi 原生基础的关系

owner 已确认：**Pi 原生系统提示词本身是资产，Work 只在其上做适量加法，不推倒重做**（PA-009）。因此必须先知道原生长什么样，才知道什么该写、什么重复。

Pi 原生提示词的最新源码依据是 `earendil-works/pi@c596d09d9cef6fdf0db2dd08f3eec8582b7fe8ba` 的 `packages/coding-agent/src/core/system-prompt.ts`；此前安装包证据为 `0.84.4` 编译产物。二者都提供下面几类内容（最新源码使用 `preamble` 以外的 `<tools>/<rules>/<docs>/<project_context>/<skills>/<cwd>` 分区）：

| 原生内容 | 说明 | 对我们的含义 |
|---|---|---|
| 身份 + “Available tools” 列表 | 只列**当前激活**的工具，逐条来自工具自己的 `promptSnippet` | 不要在主正文重列工具清单或每个工具的用途 |
| Guidelines | 内置 `Be concise in your responses`、`Show file paths clearly when working with files`，加上**所有激活工具的 `promptGuidelines`**（去重） | 简洁/路径类要求已被覆盖；新行为规则可通过工具的 `promptGuidelines` 随工具出现，而不必都塞进主正文 |
| `<project_context>` / `<project_instructions>` | 项目专属指令由 AGENTS.md 等上下文文件注入，标注路径 | **项目专属内容有正规通道**，绝不写进通用正文（PA-010） |
| Skills、Pi 文档指针、CWD | 文档指针仅在关于 Pi 自身时读取 | 正文不需要解释 Pi 的文档结构 |

正文因此遵守两条纪律：

1. **不重复原生已说的内容。** 修订 3 据此删除了“简洁/列路径”的重复表述和逐工具用途枚举（正文由 5,945 → 携带新规则后 6,185 字节，净增 240 字节而不是 400+）；修订 4 继续保持该纪律，三仓库加法后正文为 8,794 字节。
2. **只用原生接缝。** 现有实现走 `before_agent_start` 追加；`promptSnippet`/`promptGuidelines` 已在使用。Pi 同时支持 `--system-prompt`（**整体替换**原生身份/工具/Guidelines/文档段）与 `--append-system-prompt`（追加）。按 PA-009 使用保留 Base 的追加路径；整体替换不是 Work 候选。PA-Q02 已关闭。
