# 工具链实测 — 2026-09-21

结论：**现有回归与基础加载通过，但整条工具链未通过**。真实 Pi 工具执行探针发现环境前置条件缺失，以及 pi-lens 工具注册后未进入活动集合的问题。此次按 owner 要求测试，没有顺带修复生产工具或改变默认集合。

## 如何复跑

```bash
npm ci
npm run check
npm run smoke:subagents
npm run smoke:web
npm run smoke:toolchain
```

最后一项新探针在不满足要求时返回非零状态，而不是把已知失败标成通过。脚本在独立临时目录中启动真实 Pi RPC，分别关闭/开启 pi-lens，检查开始/工具配置切换/按需激活后的工具集合，并检查发往模型端点的实际 schema。完成后停止 Pi 并清理自己创建的目录。

当前运行时尚未迁移为 Chat/Work；探针通过兼容命令进入与 Work 继承工具对应的配置，不以命令名称冒充新模式验收。

模型端点是本机固定响应服务器，只发送预定工具调用；工具本身由真实 Pi 执行。Web 结果也是本机合成数据。**这验证执行与接线，不评价真实模型是否会正确选择工具，也没有调用真实 Serper 或真实模型账号。** pi-lens 自动安装被关闭，状态/日志指向独立临时目录。

## 需要处理的问题

1. **环境准备**：User VM 安装并验证 rg、fd；确认普通执行与登录 shell 都能找到部署使用的 Node。不要把临时工作区的绝对路径写死进产品配置。
2. **pi-lens 接线**：`src/harness/extension.ts` 应用/恢复工具表时显式调用 `setActiveTools`；当前工具表和能力目录没有纳入语言工具。需定义与 pi-lens 自有动态激活的协作方式，并覆盖会话开始、切换、恢复与模型切换。当前不是语言服务返回错误，而是模型根本看不到工具。
3. **下一轮真实语言验收**：接线通过后，用小型真实语言项目验证定义、引用、诊断、修改后诊断刷新；不能把这次注册成功算作 LSP 功能通过。

Chat 零系统提示词、真实模型决策质量、真实 Serper、目标部署 VM 与浏览器故障验收不在本轮通过范围。Gitea 当前不可达，本地结果待同步；未更新或关闭外部工单。

## 真实模型补充

随后使用本机 Pi、`eidolon/gpt-5.6-terra` 和用户级最新版 `pi-lens 4.2.1` 完成了真实模型对照。模型会主动选择基础工具，并成功发现、激活和调用 Web 与子 Agent；完整栈仍把所有 pi-lens 工具排除在 active 集合之外。pi-lens 单独运行时项目索引和 AST 工具可用，但 LSP 诊断为 inconclusive，所有导航查询为空。详细证据见[真实 Pi Agent 工具链测试](./real-agent-toolchain-20260921.md)。
