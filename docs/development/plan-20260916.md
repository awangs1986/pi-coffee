## 2. 复用优先规则（所有任务适用）

1. 先读对应实现和测试，复现缺口；优先补当前公共接口，不另起 Host、Web、Relay、会话层或前端框架。
2. Pi 登录/provider/model registry、Pi RPC、上游 subagent 执行器、context-fold 算法、pi-web-access 正文工具保持复用。锁定版本，先做兼容探针，不为猜测的问题替换依赖。
3. 复用 `src/shared/protocol.ts` 的帧协议；新增字段/消息要保持旧会话和客户端兼容，并写迁移/拒绝路径测试。
4. 必须新增的业务逻辑仅限缺失的用户路由、项目元数据、worktree/合并互斥、归档和文件授权等小模块；沿既有 server/session/transfer 接入，不复制一套框架。
5. 不建新沙箱、权限内核、VM manager、自动开发 Gate、Web PR 管理器、网页三方冲突编辑器；不引入无性能证据的 Rust 重写。
6. 多任务并行优先只读调查和独立文件集。同一接口/状态迁移由一个任务负责；需要跨模块修改时先确认契约，避免多个实现者同时改 `session.ts`/协议/UI 主状态。
7. 每项先 red → green，检查 diff，记录实际运行的测试和未覆盖边界。禁止用“stub 通过”替代真实 provider/VM 证据。
