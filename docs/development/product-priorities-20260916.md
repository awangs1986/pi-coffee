# 双用户 VM 工作台：P0–P5 产品排期

日期：2026-09-16。按 owner 澄清，本排期只覆盖讨论 Pi Agent 精简之前确认的产品 SPEC；不把提示词、上下文、搜索或 subagent 改造排入主线。

主合同：[multi-user-vm.md](../spec/multi-user-vm.md)。本表替代 [旧混合计划](./plan-20260916.md) 中的产品优先级；旧文件保留作为 Pi/工具未完事项的交接记录。

P0–P5 是执行顺序，不是六个版本；全部属于首版范围，P5 也是必需发布门禁。这里只排任务，不表示已实现、已认领或已创建远端 Issue。

> **2026-09-19 架构更新已确认**：统一 Web 为轻量登录／路由／聊天和文件流式网关，用户 VM 仅私网可达；公网入口 HTTPS。复用原生 Pi/Git/插件，不增加 VM 内必需 Web 层。文件网关与浏览器缓存是待开发项，不因本排期更新而标完成。见 [ADR-0010](../adr/0010-unified-web-gateway-private-user-vms.md)。

## 共用原则

- 先核查现有实现和测试，能复用的不重写；继续使用现有 Host/Web/Relay、Pi adapter、原生认证、会话历史、WebSocket、transfer 和前端渲染。
- 只补缺失的业务状态、授权、项目/工作区生命周期和交互，不另造 Agent、聊天框架、Git 引擎、VM manager 或权限内核。
- 每阶段都做公共接口回归、失败路径和数据兼容测试。身份隔离、浏览器断开不杀任务、无自动副作用重放从 P0 起就是持续约束，不等到 P4/P5 才处理。
- 旧会话/上传/用户代码不得因改造被静默迁移或删除；布局、分支命名、合并策略等未定工程细节在对应任务内记录，不扩张产品范围。

## P0：身份、固定 VM 路由与原生模型来源

**目标：先证明“登录后进自己的 VM，用自己的模型”，才能接入项目和文件。**

- P0-01：Gitea OAuth → 用户 → 固定 VM/Host；缺路由、离线、授权失败拒绝，不回退共享 Host；HTTP/WS Origin、Cookie、退出、过期、停用与路由撤销一致处理。
- P0-02：原生 Pi 认证默认，用户在 VM 终端配置；可选管理员 Relay 与原生来源可区分、可显式选择；失败不自动切来源。不重写登录或 token 刷新。
- P0-03：两用户会话/文件授权边界，Web 不持久化正文，管理员仅路由和健康；记录真实认证刷新/进程配置生效方式。
- 复用：`src/web/{server,host-client}.ts`、`src/host/{server,pi-adapter}.ts`、`src/relay/`、现有模型列表和连接鉴权。
- 验收：两账号进入各自 Host，跨用户请求拒绝；原生与 Relay 来源测试；AC-01～04。真实供应商测试需要实际 VM 用户配合，不把凭据放入聊天或 fixture。

## P1：项目四入口与每对话独立工作区

**目标：让每个对话有确定、可恢复、可并行的 Git 工作位置。**

- P1-01：固定根目录、项目注册、默认分支；每对话目录/worktree/branch/cwd，支持默认或指定起始分支；文档和研究项目同样进入 Git。
- P1-02：四入口全部实现：手动 clone 发现、Web Git URL clone、空项目、压缩包导入。覆盖空仓库、导入失败、路径/链接逃逸及展开体积上限。
- P1-03：元数据恢复、旧会话兼容；同项目多个对话独立运行，失败不产生假成功项目。
- 复用：`src/host/{session,server,pi-adapter}.ts` 的创建/恢复链路、已有上传通路、原生 Git；只补项目元数据及生命周期。
- 依赖：P0 身份/路由契约。验收：AC-05/06；两用户各三个对话是验收负载，不是产品数量上限。

## P2：用户确认的本地合并与项目锁

**目标：并行工作之后能安全、明确地把结果合回来。**

- P2-01：用户触发合并 → 看 diff → 明确确认；执行前复查源/目标 heads 与脏状态，避免确认后内容变化。
- P2-02：项目级合并锁与重复请求幂等；拒绝脏目标、冲突明确、不静默覆盖；锁崩溃恢复可查，其他 worktree 继续工作。
- P2-03：Agent 可以 commit，但平台不自动 turn-end commit/merge；远端 push/PR 交现有工具，不做 Web PR 管理器或三方冲突编辑器。
- 复用：Harness 原生 Git adapter、现有 diff 渲染、P1 工作区元数据；新增小型合并协调，不重写 Git。
- 依赖：P1。验收：AC-07，覆盖并发合并、目标脏、heads 变化、冲突及失败恢复。

## P3：文件树、上传列表、预览与下载

**目标：工作区文件和生成产物真正可见、可打开、可下载。**

- P3-01：当前工作区只读树、刷新、上传列表；文件授权绑定用户与 workspace，浏览器只访问统一同源入口；入口按用户路由有界流式转发到既有 VM 文件服务，不在入口持久化／临时落盘正文，不要求浏览器直达 VM。
- P3-02：图片、SVG、Markdown、文本、PDF 预览。图片消息默认展开，点击新标签；普通链接新标签；图片/Markdown 保留下载；SVG 必须可见但不执行脚本。
- P3-03：未授权/跨用户/路径穿越/链接逃逸拒绝，大文件有界，失效引用可解释；不做文件树编辑器、整个 VM 文件管理器、桌面或服务端口预览。
- P3-04：浏览器有限历史缓存与原生历史按需加载，按主 SPEC §7.4 的 200 MiB／20000 条、7 天主动对话、有限预取、独立草稿与身份规则实现；不另建聊天数据库。
- 复用：`src/host/transfer.ts`、`public/{app,render,diff}.js`、现有净化器/CSS/上传下载测试；只补差额。
- 依赖：P0/P1；接口稳定后可与 P2 并行。验收：AC-08/09，必须有实际浏览器证据。

## P4：归档、安全删除与完整连续性

**目标：长期使用不丢成果，多个窗口与故障恢复语义一致。**

- P4-01：主界面只归档，保留代码/历史/文件；永久删除仅在归档页，说明关联资源及未合并成果并明确确认，不顺带删除共享项目。
- P4-02：运行/合并/删除互斥，服务端权威状态驱动多窗口同步，重复请求不产生二次副作用。
- P4-03：复核浏览器关闭/断网/Web 重启任务继续；Host/Pi/VM 重启历史保留、显示中断、不自动续跑；后台完成可见，401/429/超时/断流可读。
- 复用：HostSession、事件游标/replay、原生 durable history、现有会话列表和前端状态；不建第二套聊天存储。
- 依赖：P1 元数据、P2 操作互斥、P3 文件资源模型。验收：AC-10～12。连续性基线从 P0 持续保护，P4 负责补齐完整生命周期。

## P5：两台真实 VM 联调与首版发布门禁

**目标：用实机证据证明前五阶段组合后能用，而非只看单测。**

- P5-01：两 Gitea 用户、两固定 VM、各自原生模型与可选 Relay；2×3 活跃对话、独立 worktree、合并/冲突、文件预览、归档/删除、多窗口与故障注入，逐项执行 AC-01～12。
- P5-02：复用部署 runbook、`deploy/uservm/` 和既有 smoke；核验统一 HTTPS 入口、仅私网开放的 VM Host/文件端点、服务用户/目录权限、升级/恢复流程；新增第三用户只加 VM 与路由，不加公网端口。管理员手动管理 VM，镜像无用户凭据/历史，克隆和快照恢复重新核查身份与路由。
- P5-03：记录对应代码版本、命令、预期/实测、失败项和恢复步骤；证据脱敏。环境不可用标待验收，不用本地 stub 代替真实通过。
- 依赖：P0～P4 必需功能通过各自门禁。Pi/工具已有能力作为底座做兼容回归，其剩余专项工作仍在独立交接记录，不挤占本产品排期。

## 执行关系与分工

主线：**P0 → P1 → P2 → P4 → P5**；P3 在 P0/P1 接口稳定后与 P2 并行，P3 的资源模型完成后纳入 P4/P5。

| 职责流（尚未认领） | 主要任务 |
|---|---|
| 身份/Host | P0，P4 服务端状态与连续性 |
| Git/工作区 | P1、P2，配合 P4 安全清理 |
| 文件/Web | P3，配合 P0 登录/来源、P4 归档和同步 UI |
| 测试/部署 | 各阶段随实现写测试，P5 统筹实机矩阵和证据 |

下一步从 P0 做现有代码核查和最小缺口清单，不先搭新框架；进入代码实现后执行 `npm run check`，真实环境验收另外留证。owner 后续已授权连续实施 P0–P4，并要求界面参考 Arena.ai。进展及未完缺口见 [增量实现记录](./p0-p4-implementation-20260916.md)；不能将本地实现直接标为全部验收完成。
